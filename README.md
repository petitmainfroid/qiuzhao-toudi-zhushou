# 秋招投递助手

一个本地优先的 Chrome/Edge 扩展：用户只维护一份结构化求职档案，在招聘网页中预览字段匹配结果，再选择需要填写的项目。

## 当前 MVP 能做什么

- 保存基本信息、教育经历、实习经历、项目经历、作品、获奖、语言能力、求职偏好和常用回答。
- 在求职档案页本地解析 PDF/DOCX 简历，并把有证据的内容直接填入现有信息表；中文字体、跨栏版式和异常文字层均在本机处理，已有非空值不会被静默覆盖。
- 识别中文与英文的常见招聘表单字段。
- 显示匹配分数、置信度和匹配原因。
- 默认选择高置信且非敏感字段；敏感和中低置信字段必须手动选择。
- 填写普通输入、文本域、原生下拉、单选、`contenteditable`，以及飞书 ATS 的可搜索自定义下拉控件。
- 记住同一网站中用户修正过的字段对应关系。
- 导出、导入或永久删除本地档案及纠错映射。

扩展不会保存招聘网站密码，不会绕过验证码，不会操作招聘网页中的文件控件，也不会点击最终提交按钮。

## 从源码安装

环境要求：Node.js 22 或更高版本，以及 Chrome 114+。当前开发基线使用 Node.js 24。

```powershell
.\init.ps1
```

脚本会安装锁定依赖并执行完整验证。也可以手动运行：

```powershell
npm ci
npm run validate
```

验证通过后，构建产物位于 `dist/`。

### 在 Chrome 中加载

1. 打开 `chrome://extensions/`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本仓库中的 `dist` 文件夹。
5. 首次安装会打开隐私说明和求职档案页面。

Edge 可在 `edge://extensions/` 中按相同步骤加载。

## 使用流程

1. 在“求职档案”中手动填写信息，或选择一份文字版 PDF/DOCX 简历进行本地解析。
2. 直接在原有信息表中检查、修改解析结果，然后点击“保存档案”；无法识别的内容保持空白。
3. 打开招聘网站中的申请表单。
4. 点击浏览器工具栏中的“秋招填表助手”。
5. 在侧边栏点击“扫描当前页面”。
6. 检查安全匹配和需要确认的字段，按需调整勾选。
7. 点击“填写已选项”。
8. 回到网页检查内容、补充验证码和附件，并由本人提交。

如果字段对应错误，展开“为什么这样匹配”，在“更改对应字段”中选择正确档案字段。此对应关系只针对当前网站保存，下次扫描会优先复用。

## 数据与隐私

- 档案、设置和字段映射默认保存在浏览器扩展的 `chrome.storage.local` 中。
- 简历文件和提取出的全文仅在当前档案页面内存中处理，不上传、不持久化；只有用户检查后主动保存的结构化字段会进入本地档案。
- 没有云端账号、遥测或分析服务。
- 扩展只在用户点击后使用 `activeTab` 读取当前页面表单，不申请永久的全网站访问权限。
- 只提取字段标签、ARIA 文本、占位符、字段名、控件类型和附近上下文；扫描不会采集输入框当前值。
- 出生日期、性别、籍贯和政治面貌等字段默认要求确认。
- 身份证号、护照号、银行卡号、密码、验证码和文件输入不进入自动填写。
- “本地数据管理”可以导出备份、导入替换或删除个人档案和字段映射。

更完整的产品隐私说明见 [PRIVACY.md](./PRIVACY.md)。

## 已知限制

- 网站更新 DOM 结构后，已保存的字段指纹可能失效，需要重新映射。
- 跨域 iframe、关闭的 Shadow DOM、Canvas 表单以及尚未适配的复杂非原生控件可能无法识别；飞书 ATS 单选下拉已适配。
- 级联省市选择、日期范围组件和动态富文本编辑器需要逐站适配。
- 小米实习生招聘页的字段来源、枚举值、安全边界与真实页只读验证见 [字段审计](./docs/xiaomi-internship-field-audit.md)。
- 浏览器禁止脚本任意设置本地文件路径，因此附件仍需用户亲自选择。
- 简历导入支持不超过 10 MB 的文字版 PDF 和 DOCX；异常文字层会使用随扩展打包的本地 OCR 兜底，但纯图片扫描件、加密 PDF 和旧版 `.doc` 仍不支持，也不会臆测缺失字段。
- `activeTab` 权限可能在页面跳转后失效；重新点击扩展图标即可授权当前页。
- 当前仅使用可解释规则匹配，尚未接入云端 AI 或语义模型。

## 开发与验证

```powershell
npm run dev
npm run typecheck
npm test -- --run
npm run test:e2e
npm run build
npm run verify:dist
npm run package
```

- `npm run validate`：类型检查、全部单元/组件测试、生产构建和权限审计。
- `npm run test:e2e`：使用本机 Chrome 运行档案、填表、动态歧义、侧边栏和隐私流程，并使用 Playwright Chromium 加载未打包扩展。
- `npm run package`：先执行完整验证，再生成并审计 `qiuzhao-profile-assistant.zip`。
- `fixture.html`：仅用于开发验证，不进入生产构建和 ZIP。
- `artifacts/`：保存视觉验证截图，不进入生产包。

## 工程结构

```text
src/domain       档案模型、迁移、验证和完成度
src/storage      本地档案仓库
src/matching     DOM 字段描述、标准字段目录和解释性匹配
src/content      扫描、写值、事件派发和内容脚本
src/mapping      网站字段纠错记忆
src/options      求职档案和本地数据管理界面
src/sidepanel    扫描、确认和填写工作流
src/privacy      首次告知与导入导出格式
src/resume       本地 PDF/DOCX 文本提取、确定性简历解析和档案合并
tests/e2e        Chrome 端到端验证
```

## 长任务接力

这是一个可恢复的长期工程。未来开发会话应先阅读：

- `AGENTS.md`：操作约束与验证协议。
- `feature_list.json`：功能状态、依赖、验收条件和验证命令。
- `progress.md`：决策、精确验证证据和下一步行动。

功能只有在验收命令通过并把证据写入 `progress.md` 后，才能标记为 `done`。

## 故障排查

- 侧边栏提示无法读取页面：确认当前标签是普通 `http/https` 招聘网页，然后重新点击扩展图标。浏览器内部页面不能被扩展注入。
- 页面扫描后没有候选：先确认档案字段已有内容；空值不会进入可填写列表。
- 页面显示值但网站没有响应：该网站可能使用非标准受控组件，需要增加站点适配器。
- 修改代码后行为未更新：重新运行 `npm run build`，然后在扩展管理页点击刷新。
