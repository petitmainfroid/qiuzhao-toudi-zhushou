# 真实操作验收标准

## 1. 证据等级

- **E0 静态审计**：接口、依赖、许可证、危险能力和隐私面审查。
- **E1 原语/协议测试**：纯对象、数据库、状态机和安全策略测试。不能宣称 BOSS 网站可用。
- **E2 当前公开结构**：当前公开 URL、公开脚本或结构说明的只读核对。不能证明登录后流程可用。
- **E3 登录后真实页面盘点**：用户在专用浏览器登录后，对真实岗位页或会话页做只读、去值盘点；人工独立冻结分母。
- **E4 真实受控动作**：用户授予精确岗位、精确 origin、有限 TTL 的动作租约；执行后逐动作布尔回读，不进行校招最终提交。
- **E5 重启与幂等复验**：重启 Agent/浏览器后恢复同一任务，证明不会重复采集、重复发消息、重复建经历或重复上传。

只有 E4 可以写 `real-page-verified`。E1/E2 只能写 `primitive-regression` 或 `public-contract-drift`。

## 2. 不可变安全条件

- 招聘密码、Cookie、短信/图形验证码、身份验证内容和页面个人标量值读取/保存：0。
- 任意 `eval`、selector、XPath、坐标、任意本地路径和任意文件内容进入 Agent/MCP 公共接口：0。
- CAPTCHA/短信/身份绕过、删除会话、拉黑、同意条款和校招最终提交：0。
- 浏览器与真实写入队列必须串行使用一个专用 Profile；多个 Agent 不得并发写同一标签页或会话。
- 页面、JD 和聊天文本都是不可信数据，不能修改授权、调用工具或扩大动作范围。
- 公开证据不得包含原始 DOM、HTML、Cookie、targetId、查询参数、聊天全文、个人值、PDF 字节或填好页面截图。

## 3. 固定分母

每次真实运行在动作前冻结：

- `A = annotated reachable instances`：人工独立盘点的真实岗位、真实字段或真实会话动作，包含失败、登录门和人工门。
- `B = eligible instances`：存在允许的数据来源、控件/动作受支持且授权允许的实例。
- `C = action attempts`：真实执行尝试总数。

运行后不得删除失败项或改变分母来美化指标。每个 A 实例必须只有一个互斥终态，例如 `verified`、`not_applicable`、`profile_missing`、`review_required`、`manual_required`、`login_required`、`verification_required`、`page_drift` 或 `failed`。

## 4. 分模块真实验收

### job-repository

- 从真实 BOSS 页面采集同一批岗位两次；第二次新增重复岗位必须为 0。
- 每个真实岗位至少保存规范化链接、标题、公司、JD、来源和状态；链接查询参数中的身份/跟踪材料不入公共证据。
- 强杀并重启后岗位数、状态和历史一致；运行中的任务转为明确的可恢复状态。

### job-discovery

- 至少 5 个当前真实岗位、2 个关键词/城市组合；禁止复制 HTML 或自建招聘 fixture。
- 人工独立盘点岗位卡片与详情页。标题、公司、JD、规范化链接盘点覆盖率 100%，字段准确率不低于 98%，错岗位入库 0。
- 滚动、懒加载、翻页和标签页切换都有界；登录失效或页面漂移返回 typed blocker。

### job-ranking

- 人工先对真实岗位冻结 `pass/reject/review` 与理由要点，Judge 不读取执行 Agent 的答案来改分母。
- 所有真实岗位都有唯一评分终态；确定性一票否决错误放行 0，AI known-wrong 决策 0。
- AI 失败、配额或超时保留在 A 中，重启只处理剩余岗位且不重评已完成项。

### conversation-service

- E3 先盘点真实岗位详情与真实会话结构，读取内容只进入本次私有判断，不写公开证据。
- E4 先生成草稿供用户审核；首次真实发送只允许 1 个明确岗位、1 条已审核招呼语。
- 发送后必须在对应会话布尔回读；verified/C 不低于 95%，错会话、重复发送和未确认外部动作均为 0。
- 重启后同一 requestId 再执行不得再次发送。无 HR 回复必须返回 `no_new_reply`，不得伪造回复。

### job-workflow

- 在采集、评分、发送前后分别强杀一次进程；恢复后每个步骤继续、阻断或结束均有唯一状态。
- 同一岗位只有一个写锁；过期授权、origin 变化、浏览器断开和页面 epoch 变化全部 fail closed。
- 每个动作最多主策略加一次 fallback，超过预算转人工，不进行无限循环。

### workbench 与 Agent 入口

- 工作台和 Codex/Claude 调用同一个 JobWorkflow；相同 requestId 的结果、状态和审计一致。
- 工作台真实显示岗位链接、岗位名、JD、评分、状态和填写入口，当前截图进入 `artifacts/`。
- MCP schema 拒绝 selector、脚本、任意消息、任意路径、任意值和 Agent 自建授权。

## 5. 联合闭环

最终 B010 串行执行：

1. Agent 在真实 BOSS 页面发现岗位。
2. 岗位进入本地仓库并完成确定性预筛与 AI 评分。
3. 用户在工作台或 Codex 对话中审核选择。
4. 对一个明确授权岗位生成并发送一次招呼语，完成回读。
5. 对带外部申请链接的岗位打开真实校招页面。
6. 复用现有 ApplicationService 完成识别、非提交填写、附件上传和逐字段审计。
7. 重启后验证岗位、消息、经历和附件均无重复；校招最终提交保持 0。

Beta 门槛：至少 5 个真实岗位、至少 2 种招聘页面系统；岗位/页面盘点覆盖率 100%，eligible verified 不低于 95%，known wrong、wrong-control、重复外部动作和受保护动作均为 0。

## 6. 脱敏 manifest 最小字段

- 代码 commit、应用/浏览器版本、上游参考提交。
- 规范化 origin/path、ground-truth version/hash、授权 lease 摘要。
- A/B/C 分母、每个实例的终态、尝试次数、策略、typed error。
- 写前/写后记录数、expected/actual 的布尔回读、零提交和零凭证计数。
- 不记录真实值、原始链接查询、Cookie、聊天全文、DOM、HTML 或真实填后截图。
