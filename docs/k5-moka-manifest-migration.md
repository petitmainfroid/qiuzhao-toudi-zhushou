# K5 Moka 保守声明迁移审计

## 结论

Moka 是当前 Ground Truth 中除飞书外复用价值最高的共享 ATS 家族。独立 ATS/GT 工作树的虎牙证据确认了 `app.mokahr.com/campus_apply/<tenant>/<site>` 公共租户、`#/candidateHome/resume` 候选人简历路由，以及 9 个分组 / 41 个逻辑字段的公共代码契约。

本节点没有复制公开代码包、原始 HTML、候选人值或认证数据，而是把“分组 id + 字段 id”重写为 `src/ats/adapters/moka/manifest.ts` 的规范化语义声明。安装版侧栏只在精确的 HTTPS 主机、校招租户路径和候选人简历 hash 同时满足时进入 K5，随后仍要求至少 3 个技术字段标记；缺失或歧义时关闭失败，不回退旧引擎。

## 41 个逻辑字段的处理

当前档案模型和公开证据可以安全承载其中 27 个字段：

- 姓名、手机、邮箱、性别、出生日期、所在地、期望城市；
- 一条或多条教育中的开始/结束时间、学校、专业、学历；
- 实习中的开始/结束时间、公司、职位、职责；
- 项目中的开始/结束时间、名称、职务、描述；
- 语言类型、掌握程度、自我描述、获奖时间和奖项名称。

其余字段保守处理：

- `experienceInfo` 工作经历不与 `practiceInfo` 共用同一组档案记录，避免把实习重复填到工作经历；
- 证件号码没有进入当前档案 schema，且属于身份敏感字段；
- 当前/期望薪资、工作年限、最高学历摘要和最近公司缺少无歧义目标；
- “项目中职责”不能冒充项目成果，“听说/读写”不能压缩成单一语言熟练度；
- Moka 标准简历页明确移除了上传分组，因此不声明附件控件；
- 公开代码证明 6 个可重复分组，却没有证明登录后 DOM 的新增/保存按钮结构。`repeatables` 暂为空，不猜按钮、不点击整页“保存”。

出生日期在统一档案目录中属于敏感字段，必须确认。证件号、未知企业题、保存和最终申请提交都不进入动作计划。

## 多自定义下拉缺陷与内核修复

首次真 Chrome parity 中，27 个支持字段有 25 个成功；第一个自定义下拉改变页面结构后，后续两个下拉仍使用旧快照引用，返回 `stale-reference`。第一次修复加入重扫后，错误收敛为 `workflow-timeout`：家族规则为了匹配重复记录把 `educationInfo[0]` 归一成 `educationinfo[]`，但页面精确重找需要保留索引。

最终内核把两类键分开：规则匹配键去除记录索引，计划中的页面定位键保留精确索引。每完成一个结构性下拉流程，编排器都重扫页面，按规则 id、精确语义键和已解析档案路径唯一重绑剩余字段；找不到唯一目标就停止，不复用旧 ref。单元测试覆盖两个连续下拉和每次变化的 snapshot/ref。

## 当前证据与边界

- exact manifest 与 URL 负例测试通过；仿冒主机、HTTP、非校招路径、非简历 hash 和带凭证 URL 全部拒绝。
- 安装版侧栏匿名真 Chrome 验收通过 27/27 个支持字段；三个自定义下拉、文本、日期、月份和 textarea 均写后回读成功。
- 独立工作经历、证件号、项目职责、企业自定义题保持原值；整页保存点击和最终提交点击均为 0。
- 所有 K5 建议为“无法比较、需要确认”，默认勾选为 0。当前匿名 UI 证据为 `artifacts/moka-k5-sidepanel.png`。
- `npm run validate` 通过 44 个测试文件 / 363 项测试；`npm run test:e2e` 通过 27/27 个串行真 Chrome 用例。

这些都是 L1 匿名结构证据，不代表虎牙或其他 Moka 租户的登录后 DOM 已验证。真实页面如未暴露上述技术键会安全停止。补充 Moka 重复记录生命周期前，必须由用户在已登录页面主动采集不含现有值的结构并确认新增/保存边界。
