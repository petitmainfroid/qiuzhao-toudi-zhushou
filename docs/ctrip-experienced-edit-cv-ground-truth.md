# 携程集团社会招聘简历编辑页 Ground Truth

## 归类与范围

- 公司：**携程集团（Trip.com Group）**。
- 招聘站点：`https://job.ctrip.com`。
- 用户提供页面：`#/experienced/personal-homepage/editCV?tabindex=2`。
- 归类：`ctrip-careers-custom` / `company-owned-custom-ats`。
- 共享 ATS 模板：否；当前证据表明这是携程自有招聘 SPA，不归入飞书、Moka、北森、智联招聘或 hotjob 家族。
- 页面类型：社会招聘候选人简历编辑器。
- 证据日期：2026-08-07。

公司明文和 ATS 家族均体现在归一化文件路径中：

`ats-corpus/ground-truth/ctrip-careers-custom/ctrip/ctrip__experienced-edit-cv__v1.json`

## 独立验收基准

公开页面不会在未登录状态直接渲染简历表单。当前 GT 来自无需凭证即可读取的首页语言字典、主路由代码包以及个人主页代码包，是一个 **public-bundle-contract**，不是扩展扫描器的输出。

当前代码契约给出的基准是：

- 7 个可见业务分组；
- 28 个逻辑控件；
- 21 个字段被组件声明为必填；
- 5 个可重复集合；
- 2 个附件入口；
- 4 个带固定选项的字段；
- 1 个人工短信验证门槛。

| 分组 | 控件数 | 主要字段 |
| --- | ---: | --- |
| 简历导入（解析入口） | 1 | PDF/DOC/DOCX 简历文件 |
| 基本信息 | 6 | 姓名、手机号、邮箱、性别、出生日期、居住城市 |
| 教育背景 | 6 | 学校、学历、专业、入学日期、毕业日期、经历描述 |
| 工作经历 | 6 | 公司、职位、开始日期、结束日期、当前任职、经历描述 |
| 技能和专长 | 7 | 语言及熟练度、技能及熟练度、证书、成绩、发证日期 |
| 自我描述 | 1 | 自我描述 |
| 作品集或附件 | 1 | 单个 PDF/DOC/DOCX 文件 |

五个可重复集合为教育经历、工作经历、语言、技能和证书。性别的契约值是 `male` / `female`；学历包含高中、大专、本科、硕士、博士、其他；语言和技能熟练度包含入门、基础、进阶、精通。

两个附件入口均声明只接受 `.pdf`、`.doc`、`.docx`，上限为 25 MB。修改已保存的手机号或国家/地区代码时可能出现短信验证码弹窗，该步骤只能由用户手动完成。工作经历中的“当前任职”会把最后一条经历的结束日期映射为站点内部哨兵值 `1900-01-01`，适配器不应把这个内部值写入用户档案。

## 在线漂移审计

运行：

```powershell
npm run audit:ctrip
```

审计只执行四次公开 GET：招聘首页、主代码包、个人主页代码包和共享招聘 API 定义代码包。它会动态解析当前 CDN 文件名，并验证：

- 社会招聘个人主页仍是受登录保护的路由；
- 编辑简历路由、模块和数据集合仍存在；
- 公开中文语言字典仍与 7/28 字段清单一致；
- 性别、学历、熟练度选项值未漂移；
- 附件格式、25 MB 上限、当前任职哨兵值和短信验证边界仍存在；
- 归一化 GT 与独立快照在字段、类型、必填、集合和选项上保持一致。

审计不会调用候选人资料、简历解析、验证码、保存或投递接口。

## 证据边界与下一步

这份 GT 可以作为扫描器输出的独立分母，但还不能证明登录后页面真实渲染了 28 个可操作控件，也不能证明填写成功。动态折叠、分页、弹窗、组件包装和现有简历状态都可能改变 DOM 表现。

下一步应由开发者本人登录携程招聘站，在侧边栏主动触发匿名结构采集，然后把采集结果与 **7 组 / 28 个逻辑控件**逐项比较。采集文件不得包含已有字段值、姓名、手机号、邮箱、文件名、Cookie、令牌或请求正文；不得触发简历解析、短信验证码、保存或最终投递。
