# K5 Ctrip Careers 保守声明迁移审计

## 归类与证据边界

携程招聘站是 `ctrip-careers-custom` / `company-owned-custom-ats`，不是可复用到其他公司的共享 ATS。本次迁移仍有价值：它验证 K5 可以承载一个带 hash 路由、短信验证门槛、两个不同语义附件入口和五个重复集合的自研招聘 SPA。

来源是独立 ATS/GT 工作树中 2026-08-07 的 public-bundle-contract：`https://job.ctrip.com/#/experienced/personal-homepage/editCV?tabindex=:tab`、7 个业务分组、28 个逻辑控件、21 个必填字段、5 个重复集合、2 个附件入口和 1 个人工短信验证门槛。登录后的渲染 DOM、候选人 API 和真实填写没有进入该证据。

## 28 个控件的处理

`src/ats/adapters/ctrip/manifest.ts` 为全部 28 个逻辑控件记录决策，其中 14 个由当前档案无歧义承载：

- 姓名、手机号、邮箱、性别、出生日期、居住城市；
- 已存在教育记录的学历和专业；
- 已存在工作记录的公司、职位和描述；
- 已存在语言记录的语言与熟练度；
- 自我描述。

其余 14 个保持手动：

- “简历导入”会触发解析并可能覆盖当前草稿，不能复用普通附件授权；
- “作品集或附件”不是明确的简历目标，不能擅自上传常用简历；
- 学校是可搜索下拉或自定义文本的双态控件，登录后实际模式未证明；
- 教育/工作日期要求完整日期，而当前档案的经历日期通常只有月份；
- 当前任职会使用站点内部 `1900-01-01` 哨兵值，不能写回档案；
- 教育描述、技能、技能熟练度、证书、成绩和发证日期没有等价档案字段。

五个集合的公开代码结构不足以证明登录后新增、保存和折叠行为，因此 `repeatables` 保持为空。当前版本只填写页面已经存在的索引 0 记录，不创建、不删除、不排序，也不点击整页保存。

## Hash 路由与短信安全

生产路由要求 HTTPS、精确主机 `job.ctrip.com`、根路径和精确的 experienced edit-CV hash；HTTP、仿冒主机、用户凭据、非默认端口、其他物理路径、其他 hash 和非数字 tabindex 都拒绝。K1 不公开 hash 查询，manifest 再通过至少三个技术字段标记确认页面。

首次清单负例测试发现通用运行时把 `pathPrefixes: ["/"]` 当成了所有同源路径的前缀。现在根路径声明只匹配精确 `/`；`/campus` 等路径在清单层也会失败关闭。

手机号写入被标记为确认操作。匿名页面证明它可以触发一次人工短信验证提示，但 K1 不读取验证码，清单不声明验证码字段，K2 不写验证码，也不会请求、发送或绕过短信验证。

## 匿名真 Chrome 证据

- 28/28 个公共控件都有声明：14 个自动处理、14 个明确手动；无选择器、脚本、DOM/CDP id 或候选人值。
- 安装版侧栏在精确 Ctrip hash 路由显示 14 个建议，默认勾选 0；不存在自动附件区域。
- 14/14 个档案字段写后回读成功，三个连续结构型下拉逐次重扫与精确重绑。
- 短信提示出现 1 次但验证码保持原值；两个文件控件、技能、证书、企业题、整页保存和最终提交均未操作。
- `npm run validate` 通过 46 个测试文件 / 393 项测试；`npm run test:e2e` 通过 29/29 个串行真 Chrome 用例。
- 当前匿名 UI 证据为 `artifacts/ctrip-k5-sidepanel.png`。

这是 L1 证据，不代表真实携程账号页面已验证。L2/L3 仍需用户登录后主动连接，并且不得采集已有值、文件名、Cookie、验证码或请求正文。
