# K5 飞书招聘声明迁移审计

## 结论

`agent/ats-observation-core` 中的飞书招聘资产不能整包复制到 K5。可复用部分是受信任的 ATS 域名后缀、申请路径形态、技术字段键、档案字段映射和重复区块按钮文案；CSS 选择器、直接 `.click()`、内容脚本写入和旧控件驱动不进入统一内核。

本节点把可复用部分改写为 `src/ats/adapters/feishu/manifest.ts`。清单通过 K5 exact-key 校验，只能声明规范化意图，由 K1–K4 内核负责页面读取、写入、回读、授权和附件上传。

## Ground Truth 来源边界

独立 ATS/GT 分支当前包含以下飞书家族公司证据：小米、MetaApp、蔚来、安克创新、禾赛科技。它们证明已审查租户使用飞书招聘的服务器字段合同和路径形态，但不能证明当前登录后的 DOM、弹层、日期、重复记录或保存行为一定可写。

生产清单因此只注册一个 `feishu-recruiting` 家族，不按公司复制代码。它接受受限的 `jobs.feishu.cn`、`jobs.f.mioffice.cn` HTTPS 后缀和已审查申请路径，并要求至少两个稳定技术字段标记。仿冒后缀、HTTP、职位详情页和缺少字段标记的页面均不匹配。

## 迁移取舍

| 原 ATS 资产 | K5 处理 |
| --- | --- |
| `basic_info.*`、`education_list[]` 等技术键 | 转为 K5 `semanticKeys` |
| 档案路径映射 | 转为 canonical profile intent |
| 飞书下拉/日期驱动名 | 转为固定 capability；不携带实现代码 |
| 重复区块路径别名 | 转为 record semantic prefix |
| 新增/保存文案和上限 | 保留为受限声明 |
| 区块、按钮、记录 CSS 选择器 | 丢弃；禁止进入 manifest |
| 直接点击、脚本注入、内容脚本写入 | 丢弃；统一由内核执行 |
| 身份证件和企业自定义问题 | 手动或未知，不自动猜测 |
| 简历附件 | 改为 K4 已保存 PDF 的单独确认 gate |
| 最终投递 | 始终排除 |

## K1 结构补强

真实飞书样本显示，交互控件本身不一定有 `name`，稳定技术键常位于最近的 `data-form-field-name` 容器，中文字段名位于 `data-form-field-i18n-name`。K1 现在最多向上检查八层，只接收格式受限的 ASCII 技术键；不合法属性不会进入状态。这个变化不暴露 CSS、DOM id、class 或网页值。

历史匿名化前的本地观察还暴露了一个隐私问题：已上传文件按钮可能把文件名和上传时间混进可访问文本。本节点在语义清洗层将常见文档文件名和同一文本中的时间替换为 `[文件]`、`[时间]`，并加入单元测试和真实 Chrome 回归。原观察文件及其中内容没有复制到 K5 分支。

## 当前证据与剩余工作

- exact manifest 合规测试通过；序列化清单中不存在 selector、脚本、浏览器命令、DOM/CDP id 或任意值。
- 小米、MetaApp、蔚来、安克创新、禾赛科技五种已审查域名/路径形态在声明级测试中均识别为同一个飞书家族；仿冒域名、HTTP 和非申请路径全部拒绝。
- 真实 Chrome 匿名飞书结构 canary 证明 K1 容器元数据继承、文件元数据去敏、K5 检测与计划生成、企业自定义题跳过和零最终提交。
- 该 canary 是 L1 匿名结构，不是任何公司的真实页面成功证明。

生产 resolver 尚未注册该清单。下一节点必须先补齐飞书写入 parity，特别是自定义下拉、双输入日期区间的唯一复合引用、重复记录新增/保存和已保存 PDF，再让安装版侧栏优先使用 K5。非飞书站点的旧路径和最终 legacy 删除属于后续迁移，不得被这个只读 canary 掩盖。
