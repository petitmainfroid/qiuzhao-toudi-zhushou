# K5 Lenovo Talent 保守声明迁移审计

## 证据结论

Lenovo Talent 是第三个进入生产 K5 路由的招聘家族。来源是独立 ATS/GT 工作树中 2026-08-07 的公开生产组件与字典审计：`https://talent.lenovo.com.cn/account/resume`、PC Element Plus 简历编辑器、7 个分组、55 个逻辑字段、2 个工作流控件和 15 个远程字典。

该证据没有登录后的渲染 DOM、候选人值或真实写入结果。本节点只重写技术字段名、类型、条件和附件约束，不复制生产代码、HTML、接口响应、认证信息或真实简历。因此当前结果属于 L1 匿名真 Chrome parity，不能声称联想真实账号页面已经成功填写。

## 55 个字段的处理

`src/ats/adapters/lenovo/manifest.ts` 对 55 个公共字段逐项声明处理结论，其中 15 个可以由当前档案与 K5 能力无歧义承载：

- 电子邮箱、手机号；
- 教育经历的学历、培养方式、专业、年级排名；
- 已存在实习记录的单位、职位、工作描述；
- 已存在项目记录的名称、职责、描述；
- 特长爱好、自我评价；
- 通过 K4 本地文件门控上传的常用简历 PDF。

其余 40 个字段保持手动，主要原因不是缺少标签，而是当前模型或内核不能可靠表达：

- “姓/名”不能从一个 `fullName` 字符串无损拆分；
- Element Plus 单选组会产生多个同名 radio 控件，K5 尚没有组级唯一引用；
- 出生、教育、实习和项目月份要求 `YYYY/MM`，当前档案是规范化 `YYYY-MM` 或 `YYYY-MM-DD`，本轮不在页面侧猜格式；
- 学校是远程搜索下拉，当前结构选择流程不会先输入查询并验证远程结果；
- 期望城市是最多三项的多选，而档案当前仍是一个字符串；
- 实习/项目“是否有”控制条件渲染，当前只读证据未证明安全的切换、创建和保存生命周期；
- 证件、头像、调剂、联想专属问题、语言考试/分项能力、编程技能、信息来源和内推码没有等价档案字段。

`repeatables` 保持为空。公共组件证明了列表 API，但没有证明登录后按钮的 DOM 引用、标签和逐条保存转换；匿名验收只填写已存在的第 0 条记录。整页“保存”和最终“提交申请”都不进入动作计划。

## 路由和安全边界

生产路由只接受 HTTPS、精确主机 `talent.lenovo.com.cn`、默认端口和 `/account/resume` 路径；带凭据、仿冒子域、非默认端口、其他路径或 SPA hash 都拒绝。进入 K5 后还必须命中至少 3 个公开技术字段标记。匹配失败或歧义时不会回退旧填写引擎。

简历附件只接受唯一的 `resumeAttachment` 文件控件，并通过已有保存 PDF、目标 Origin、用户确认和 K4 上传授权。头像控件、解析确认、区块确认、整页保存和最终投递均不复用该权限。

## 匿名真 Chrome 证据

- 清单契约覆盖 55/55 个公共字段：15 个自动处理、40 个明确手动；清单没有选择器、脚本、DOM/CDP id 或候选人值。
- 安装版侧栏在匿名 Lenovo 路由显示 14 个档案建议，全部默认未勾选；PDF 位于独立的再次确认区域。
- 14 个档案字段全部写后回读成功，3 个连续 Element Plus 风格下拉逐次重扫与精确重绑；保存 PDF 上传并验证 1 次。
- 姓、名、生日、证件、微信、远程学校、月份、头像、企业题保持原状；整页保存点击 0，最终提交点击 0。
- `npm run validate` 通过 45 个测试文件 / 377 项测试；`npm run test:e2e` 通过 28/28 个串行真 Chrome 用例。
- 当前匿名 UI 证据为 `artifacts/lenovo-k5-sidepanel.png`。

下一步若要提高 Lenovo 覆盖率，应先在通用内核增加 radio-group 组级引用、显式日期格式转换、远程搜索下拉和多选值模型，再用用户授权的去值 DOM 观察证明条件区块与重复记录生命周期。不能通过为 Lenovo 写直接 DOM 操作绕过这些通用能力。
