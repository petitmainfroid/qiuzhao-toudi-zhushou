# 简历 PDF 附件：威胁模型与真机验收标准

## 目标与安全结论

允许用户在扩展侧边栏中选择一个 PDF，在看见文件摘要、目标 HTTPS Origin 和唯一简历控件后，亲自确认一次附件动作。确认可能立即触发招聘网站上传，因此确认必须发生在页面文件控件收到 `File` 之前。

首选架构是“扩展内存中的 File”：侧边栏通过用户文件选择手势取得文件，验证文件名、MIME、大小、PDF 文件头和 SHA-256；内容脚本只接受与当前 Origin、唯一简历控件、摘要和 60 秒时限绑定的一次性授权。文件原文、路径和字节不写入 `chrome.storage`、日志、截图或 Git。

OpenCLI/DevTools 只保留为兼容性后备。如果某个 ATS 明确拒绝由内容脚本构造的 `File`，后备方案也只能接受扩展生成的 opaque 单次 token；禁止 agent 提交任意路径、选择器、文件控件或 JavaScript。

## 架构对比

| 维度 | 扩展内存 File（首选） | OpenCLI/DevTools token（后备） |
| --- | --- | --- |
| 文件来源 | 用户在侧边栏亲自选择 | 用户选择后由本地伴随程序持有 |
| 路径暴露 | 不读取、不传递路径 | 伴随程序可能接触路径，必须 token 化隔离 |
| 权限 | 维持 `activeTab`、`scripting`、`sidePanel`、`storage` | 需要额外本地组件和严格页面绑定 |
| 页面目标 | 内容脚本重新识别唯一简历 input | DevTools 可直接设置 input，但风险更高 |
| 重放防护 | 60 秒、单次、Origin/元素/摘要绑定 | 同样要求，且 token 不得携带路径 |
| 默认选择 | 是 | 否；仅在真机证明首选路径失败后启用 |

## 信任边界与攻击面

- 文件选择：只接受用户手势产生的单个 `application/pdf`，文件名不得包含路径，大小必须在 1 字节至 10 MiB。
- 控件发现：必须只有一个高置信简历文件控件；身份证、护照、照片、成绩单、作品集、推荐信和资格证控件全部排除；多个候选时停止。
- 确认：显示文件名、大小、SHA-256 前缀、目标 Origin 和控件标签。点击确认后生成 60 秒一次性授权；第一次尝试无论成功失败都消费授权。
- 传输：内容脚本重新检查 Origin、控件和页面现有文件状态，重新计算摘要并验证 `%PDF-` 文件头，然后设置一个 `File` 并派发 `input/change`。
- 立即上传：很多 ATS 在 `change` 时立刻发请求，而不是最终提交时才上传。因此“确认上传”就是网络传输确认，不能和普通安全填表共用默认选择。
- 输出：只返回成功/失败码；不返回页面已有文件名、服务器响应正文、Cookie、认证头、文件路径或字节。
- 终止：绝不点击最终提交；不处理验证码、登录、身份检查或其他附件。

## 自动化验收门槛

### A. 本机 Chrome 仪器化页面

1. 页面包含一个 PDF 简历控件、一个身份证附件控件和最终提交按钮。
2. 选中文件但未点击确认时，页面 `files.length` 为 0，上传请求数为 0，提交数为 0。
3. 错误摘要、错误 Origin、过期授权、多个简历控件和授权重放均失败，上传请求数保持 0。
4. 点击确认后，唯一简历控件恰好收到一个 PDF，身份证控件保持空，`change` 恰好一次。
5. 若页面在 `change` 时上传，网络观察恰好出现一次附件请求；最终提交数仍为 0。
6. 截图只能使用合成文件名和合成页面数据。

### B. 未打包扩展真机门槛

1. 使用真实 Chrome/Edge 加载当前 `dist/`，扩展权限仍为四项最小权限。
2. 用户在目标招聘标签页点击扩展图标后扫描；侧边栏只在唯一高置信简历控件存在时显示附件卡。
3. 用户选择 PDF 后，侧边栏显示文件名、MiB/KiB、摘要前缀、完整 Origin 和控件标签；此时 Network 中没有新增附件请求。
4. 确认后页面显示已选择/已上传状态；刷新或再次确认不能重放旧授权。
5. 页面跳转、Origin 变化、控件替换、已存在文件和超过 60 秒都必须停止并要求重新扫描。
6. 整个流程没有最终提交点击或申请提交请求。

### C. 真实招聘网站通过标准

真实网站只有在用户明确给出或确认“具体 PDF + 精确 HTTPS Origin”后执行：

1. 记录浏览器版本、扩展版本、时间、精确 Origin/路径模板和控件标签；不记录 query token、Cookie、页面值或文件内容。
2. 确认前完成 30 秒网络观察，证明选择动作尚未把文件发送到站点。
3. 用户核对文件摘要、站点和控件后亲自点击确认；只允许一次附件动作。
4. 记录结构化结果：候选数、授权是否消费、文件控件是否接受、附件请求计数/状态类别、最终提交点击数和申请提交请求数。所有个人值必须脱敏。
5. 通过条件：唯一正确控件接受 PDF；若站点立即上传，只有一次预期附件请求；身份/其他附件保持不变；最终提交和申请提交请求均为 0。
6. 失败即停止：候选不唯一、站点跳转、控件漂移、服务器拒绝、需要验证码或无法区分附件请求与申请提交请求时，不得继续尝试其他控件。

## 当前证据边界

本地仪器化页面可以证明浏览器 `File` 流程、摘要绑定、单次授权和 `change` 即上传的确认位置。它不能替代真实 ATS 证据。真实招聘网站仍需要用户在已登录真机标签页完成工具栏授权，并在看见具体文件、Origin 和控件后确认可能发生的网络传输。
