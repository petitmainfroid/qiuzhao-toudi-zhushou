# F055 聚焦字段补填验收标准

## 产品位置

- 默认流程仍只有“自动填写当前页面”一个主操作。
- 补填入口只在完成一次自动填写分析后，以“某个字段没填上？”折叠项出现。
- 它是漏填后的单字段逃生通道，不提供扫描、批量选字段或最终投递能力。

## 成功路径

1. 内容脚本已经由前一次自动填写手势注入。
2. 用户在招聘页亲自点击一个空白、普通、可编辑字段，或用 Tab 键把焦点移入该字段。
3. 用户在侧边栏点击“读取刚刚聚焦的字段”。界面只显示该字段的结构标签和控件类型，不显示网页现值。
4. 用户从仅含非敏感、非空本地档案字段名称的列表中选择一项。列表不展示任何档案值。
5. 侧边栏只把所选路径和一个所选值发送给内容脚本；不会为此操作传入整份档案。
6. 内容脚本重新核对页面地址、60 秒时限、用户焦点、结构指纹、空值状态和控件安全性，使用既有控件适配器写入并回读验证。
7. 授权只使用一次，结果只返回字段名称、成功状态或类型化失败原因，不返回写入值。

## 必须失败关闭

- 没有用户聚焦手势、焦点或授权超过 60 秒。
- 页面跳转、字段被移除、结构指纹变化或用户改点另一个字段。
- 网页字段已有内容；冲突必须回到集中确认流程。
- password、file、hidden、button、checkbox、禁用、只读、不可见、日期区间或提交类控件。
- CAPTCHA、短信码、OTP、身份验证控件。
- 目标字段被识别为敏感字段，或所选档案字段带 `sensitive` 标记。
- 档案路径不存在、值为空、控件适配器不支持或回读不一致。

## 隐私与投递边界

- 不读取或返回招聘页当前原始值。
- 补填选择器只显示字段名称；敏感档案字段完全不进入列表。
- 内容消息只携带用户选中的一个值，不携带 Cookie、密码、附件、整页 HTML 或整份档案。
- 不增加浏览器权限，不执行网络请求，不点击任何保存卡片、提交申请或投递按钮。
- 本功能是对参考产品交互边界的 clean-room 重实现；不复制其 bundle、私有 API、品牌、资产、选择器或源码。

## 验证证据

- `npm test -- --run src/sidepanel src/content`
- `npm run validate`
- `npm run test:e2e -- --grep "manual recovery"`
- `artifacts/manual-recovery.png` 应显示 Organic 样式、折叠的次级补填区、一个已锁定字段、仅标签的档案选择器，以及页面上不存在提交/投递操作。
- 静态检查消息协议不得在 `FILL_FOCUSED_RECOVERY` 中携带 `CandidateProfile`，实现不得包含远程请求或最终投递动作。
