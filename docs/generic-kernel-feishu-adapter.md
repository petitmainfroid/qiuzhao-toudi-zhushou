# 通用填写内核与飞书招聘 ATS 家族适配

## 结论

项目现在按“一个通用内核 + 多个 ATS 家族适配器”组织。飞书招聘是第一个接入这套边界的家族；小米、蔚来、MetaApp、安克创新和禾赛不再各自拥有一套填写逻辑。

这不是“发现飞书域名后直接盲填”。家族检测只决定使用哪份已审查的结构规则，实际写入仍由通用安全内核逐字段执行、回读并验证。

## 模块边界

通用内核负责：

- 从页面提取字段描述，执行通用确定性匹配和站点级纠错覆盖；
- 生成值、比较网页已有内容、阻止过期映射和未经确认的冲突；
- 按模板指定的控件驱动写入，并在最多两次尝试内完成回读验证；
- 按模板规则扫描、新增和保存教育、实习、项目等重复记录；
- 永久排除密码、验证码、CAPTCHA、隐藏字段、普通文件字段和最终投递控件。

飞书招聘家族适配器负责：

- 识别受信任的 `*.jobs.feishu.cn` 与 `*.jobs.f.mioffice.cn` HTTPS 租户及已审查的申请路径形态；
- 将 `basic_info.*`、`education_list[]`、`internship_list[]` 等稳定语义键映射到本地档案路径；
- 声明普通输入、飞书下拉、飞书日期区间各自使用的驱动与验证策略；
- 声明重复区块的路径别名、区块/按钮/记录选择器、允许的新增/保存文案和单次创建上限；
- 明确附件和最终投递控件不可进入普通自动填写。

默认组合位于 `src/ats/defaultTemplates.ts` 和 `src/ats/defaultRuntime.ts`。通用 `AtsMatchingRuntime` 只接收注册表，不导入任何具体 ATS 家族。

## 执行顺序

1. 用户在当前招聘页主动点击自动填写。
2. 内容脚本临时读取控件结构，通用运行时识别 ATS 家族并选择模板。
3. 模板规则先做确定性字段映射；用户保存的站点纠错只覆盖字段路径，不改写安全边界。
4. 通用内核比较档案值与网页已有状态，冲突或敏感信息继续要求确认。
5. 写入时严格使用模板声明且与真实 DOM 兼容的驱动；不兼容时跳过，不降级为随意输入。
6. 每次写入都回读；招聘网页没有接受目标值时返回失败。
7. 重复经历按模板规则逐条创建、每次重新扫描，并只点击记录内部明确匹配的保存控件。
8. 扩展停在已填写页面，最终投递仍由用户点击。

## 当前证据边界

- 自动化测试已经覆盖小米、蔚来、MetaApp、安克创新和禾赛的已采样域名/路径形态，以及飞书标准语义字段、下拉、日期区间、重复区块和最终投递排除。
- 仓库中的公开服务器 Schema ground truth 可以证明这些租户使用相同的飞书招聘字段合同，但不能单独证明登录后的真实 DOM 在每次改版后都能成功填写。
- 现有匿名 observation 可用于发现结构差异；它不是候选人数据，也不能替代真实页面的人工核对。
- 因此当前结论是“已具备飞书家族检测与确定性适配基础”，不是“所有飞书招聘页面已经完成真实投递验证”。新增自定义问题仍应先进入通用匹配或人工确认，不能凭公司名称猜测。

## 扩展其他 ATS 家族

新增 Moka、北森等家族时，应新增独立的 detector/template 模块并注册到默认组合。不得在 `src/content` 中增加公司 URL 分支，也不得复制填写、回读、冲突确认或最终投递保护逻辑。
