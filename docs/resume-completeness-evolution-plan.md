# 简历完整性与正确性演进方案

## 目标

最大化“简历中有明确证据、档案结构能够表达、招聘网页能够安全填写”的信息覆盖，同时保持不编造、不覆盖已有档案、不上传原文件、不读取登录凭据、不绕过验证和不提交申请。

DeepSeek 只负责提出候选缺陷。是否正确、是否晋升，始终由源证据、规范档案路径、匿名回归测试和浏览器写入结果决定。

## 三段覆盖链

1. **源简历 → 结构化档案**：检查支持字段是否缺失、值是否错位、记录是否串联、章节是否泄漏。
2. **结构化档案 → 网页空位**：使用现有确定性 matcher 检查字段路径、重复记录创建、值比较和精确写入。
3. **安全边界**：文件、密码、验证码、证件、身份附件和最终提交不进入批量填入。

“字段数量更多”不是充分条件。新增值必须有源证据，错误路径和邻接章节污染会降低正确性。

## 隐私边界

- 只扫描 `evals/resume-corpus-manifest.json` 中的短摘要白名单，不使用文件名发现语料。
- PDF/DOCX 原文件、路径、未清洗文本和 API Key 不写入产物、不打印、不提交。
- 外部请求前移除姓名、电话、邮箱、证件号、URL、街道地址和已解析的敏感基本信息；模型只看到编号行、摘要和规范路径。
- 模型输出只保留枚举状态、规范路径、行号、严重度、置信度、原因码和布局码，不保存原文摘录。
- 扩展运行时保持完全离线；只有开发者显式运行 `--judge` 才会调用 `.env` 中的 HTTPS Boyue 兼容接口。

## 判定与停止规则

- `missing` 必须对应源中明确存在、档案支持且当前路径为空的值。
- `incorrect` 必须对应当前已填路径，并能由编号行证明错误、错记录或章节泄漏。
- “至今”不生成结束日期；裸 CET 分数不推断口语熟练度；论文年份不自动成为项目周期；描述与成果可互补保存。
- 模型校准未满分、模型标识不匹配、响应不合法、隐私断言失败或 HTTP/重定向均失败关闭。
- 全量真实简历评审成本高且存在长尾。初始基线后，只对新增匿名回归或受改动影响的摘要使用 `--sample=<DIGEST>` 定向复评。
- 一轮只晋升一个确定性修改；若模型意见无法缩成匿名反例，则停止继续询问。

## 命令

```powershell
# 本地 Chrome 读取摘要白名单并生成去标识观测，不调用模型
npm run eval:resume -- --offline

# 全量 DeepSeek 候选审计；成功结果逐份写入忽略的可恢复检查点
npm run eval:resume -- --judge --skip-browser

# 修改后只复评受影响摘要
npm run eval:resume -- --judge --skip-browser --sample=5A12C901
```

忽略的产物位于 `artifacts/resume-completeness-*.json`。稳定工程证据只记录摘要、计数、命令结果和匿名回归，不记录任何真实值。
