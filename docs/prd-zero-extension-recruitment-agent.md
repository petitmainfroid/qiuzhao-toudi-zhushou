# 秋招 Agent：零浏览器扩展方案 PRD

- 文档状态：已评审基线（implementation-ready）
- 版本：v1.0
- 日期：2026-08-12
- 产品形态：本机桌面 Agent + 求职专用浏览器会话
- 适用平台：Windows 优先，macOS 后续
- 当前代码基线：Chrome/Edge 扩展原型，具备本地档案、规则匹配、ATS 适配、验证写入和字段审核能力

## 1. 产品决策

本项目从“用户安装浏览器扩展后，在侧栏中逐页操作”迁移为“用户安装一个桌面应用，由应用启动并控制求职专用浏览器”。正式产品不得要求安装 Chrome/Edge 扩展，也不得依赖扩展商店、开发者模式或“加载已解压扩展”。

用户首次完成桌面应用安装、档案录入和招聘网站登录后，日常主流程只有两种入口：

1. 在单个岗位卡片点击“自动填写”。
2. 勾选多个岗位后点击一次“开始本批次”。

随后 Agent 自主打开页面、识别字段、创建必要的经历记录、填写、回读验证并生成逐字段审核报告。验证码、短信验证、身份核验、敏感信息确认、不可逆外部沟通越界和最终申请提交始终停给用户处理。

“零浏览器扩展安装”不等于“零软件安装”或“无授权控制用户已有浏览器”。MVP 需要安装一次桌面应用，并使用隔离的求职专用 Chrome/Edge 用户目录。Chrome 136 起，远程调试参数不能用于默认浏览器数据目录，必须配合非默认 `--user-data-dir`；因此产品不承诺无感接管用户已经打开的日常 Chrome。[Chrome 官方说明](https://developer.chrome.com/blog/remote-debugging-port)

## 2. 问题与机会

### 2.1 当前问题

- 扩展需要下载、解压、打开开发者模式、加载目录，首次使用成本过高。
- 扩展受用户手动连接、扫描、切换标签页和侧栏状态影响，难以形成完整的 Agent 闭环。
- “扫描成功”与“字段真实填写正确”混在一起，无法回答每个招聘字段为什么已填、空白或失败。
- 同一 ATS 不同公司会更换字段叫法、组件和页面步骤；针对单页硬编码会破坏同族其他页面。
- 模拟招聘页可以验证底层控件，却不能证明真实小米、安克、蔚来、虎牙等页面可用。
- 当前扩展运行时与 Agent/CLI 能力并存，控制权、授权范围和证据口径不统一。

### 2.2 产品机会

将现有的档案、匹配、适配器、验证写入和审计模块放到独立浏览器内核之上，可以形成一个可恢复、可评测的本机 Agent：它既能完成校招表单，也能在后续承担 BOSS 直聘中的岗位筛选和有界沟通，而不需要在每个网站安装或维护扩展。

## 3. 目标、非目标与成功定义

### 3.1 产品目标

G1. 用户不安装任何浏览器扩展，也能在可见浏览器中完成招聘表单的自动填写和逐字段审核。

G2. 对页面中每个可达逻辑字段给出唯一、明确、可追溯的结论；空白字段必须区分档案缺失、程序失败、安全阻断、条件不适用和需要人工处理。

G3. 用户对一个明确岗位或一批明确岗位授权一次后，Agent 不再要求逐字段、逐步骤点击；只有越过安全边界时暂停。

G4. 同一 ATS 采用“通用浏览器内核 + ATS 家族适配 + 公司级数据覆盖”的分层方式，不因修复安克而破坏小米。

G5. 所有站点兼容性结论来自用户授权的真实招聘网页。模拟招聘页、公开静态 HTML 或模型判断均不得替代真实写入证据。

G6. 后续复用同一内核支持 BOSS 直聘岗位浏览、候选岗位排队、消息草拟以及用户批准范围内的自动沟通。

### 3.2 非目标

- 不绕过 CAPTCHA、短信、人脸、扫码或身份核验。
- 不读取、导出或保存招聘网站密码、Cookie、Authorization、会话令牌或默认浏览器资料。
- 不点击最终“提交申请/确认投递”控件。
- 不使用虚假身份或虚构经历污染真实招聘系统。
- 不承诺接管用户当前已经打开的默认 Chrome 标签页。
- 不在 MVP 中规避招聘平台风控或平台条款。
- 不把云端大模型作为字段真值、网页驱动器或写入成功判定器。

### 3.3 北极星指标

`无需扩展且完成逐字段审核的真实申请草稿数 / 用户授权处理的真实申请页数`。

发布门槛：

| 指标 | 定义 | MVP 门槛 |
| --- | --- | --- |
| 扩展依赖 | 产品完整主流程中安装或调用本项目扩展的次数 | 0 |
| 字段盘点率 | 已产生审核结论的可达逻辑字段 / 独立标注的可达逻辑字段 | 100% |
| 可自动填覆盖率 | 成功回读字段 / 有档案来源且允许自动填写的字段 | 每页 ≥90% |
| 验证写入成功率 | 写入且回读一致字段 / 所有允许写入尝试 | 每页 ≥95%，总体 ≥98% |
| 映射正确率 | 写入正确档案路径的字段 / 所有执行写入字段 | ≥98%，发布集零已知错误写入 |
| 结论完备率 | 具有唯一结论、来源与证据的字段 / 全部字段 | 100% |
| 禁止动作 | 密码/Cookie/CAPTCHA 绕过/未确认敏感信息/最终提交 | 0 |
| 重复记录 | 恢复或重跑后新增的重复经历记录 | 0 |
| 崩溃恢复 | 可从最后验证检查点安全继续的中断批次 | 100% |

## 4. 目标用户与核心场景

### 4.1 目标用户

- 正在集中投递校招、实习岗位，需要反复填写相同经历的求职者。
- 拥有结构化简历，但无法判断自动化是否覆盖了页面全部字段的用户。
- 希望 Agent 处理机械工作，自己只审核敏感项、验证码和最终提交的用户。

### 4.2 核心场景

1. 单岗位自动填写：岗位卡展示网页链接、岗位名称、JD 和“自动填写”。
2. 多岗位批量处理：用户选择一批真实岗位并一次授权，Agent 顺序处理，在阻断点暂停。
3. 填写结果审核：每个页面字段都有网页状态、档案来源、动作证据和审核结论。
4. 失败回归：真实页面失败被归类为可复现缺陷，经修复后在同一真实页面重新授权验证。
5. BOSS 有界沟通：用户批准一个沟通批次和规则后，Agent 可发送允许类型的消息并保留审计记录。

## 5. 产品边界与证据等级

### 5.1 “真实网页”的定义

满足以下条件才算真实网页证据：

- URL 指向招聘企业或 ATS 当前线上页面，而非本仓库、本机服务器或复制页面。
- 页面来自当次真实浏览器会话；公开 schema 只能证明结构来源，不能证明控件可写。
- 需要登录时，由用户在求职专用浏览器中自行完成登录。
- 写入使用用户真实且愿意提供给该招聘方的档案值。
- 不提交申请；若网站会自动保存草稿，必须在授权前告知用户。

### 5.2 证据等级

| 等级 | 证据 | 可以证明 | 不能证明 |
| --- | --- | --- | --- |
| E0 | 类型检查、静态安全审计 | 协议和禁止动作在代码层存在 | 浏览器可连接、站点可用 |
| E1 | 单元测试、最小无品牌 DOM/控件测试 | 算法、协议、控件原语行为 | 任意招聘网站兼容性 |
| E2 | 当前真实公开 URL/schema，只读 | 页面身份、字段契约和漂移 | 登录后 DOM 或填写成功 |
| E3 | 用户登录后的真实页只读盘点 | 可达字段、控件和步骤分母 | 字段能够正确写入 |
| E4 | 用户授权的真实页非提交写入 | 该页面当前版本可填写、可回读 | 同 ATS 所有公司永久兼容 |
| E5 | 打包版跨重启、跨版本真实验收 | 产品级安装、恢复和升级可用 | 未进入验收集的网站可用 |

规则：只有 E4 可以把某个页面标记为 `real-page-verified`。只有来自至少三个不同公司、相同 ATS 家族的 E4 证据，才能将公共能力标记为“家族级已验证”。

现有模拟招聘页不得再用于站点支持结论。底层单元测试可保留最小、无品牌的控件状态，但测试名、文案和报告不得冒充小米、飞书、Moka 等真实兼容证据。

## 6. 产品形态与信息架构

### 6.1 桌面首页

首页只保留对用户决策有用的信息：

- 档案完成度和缺失项。
- 求职专用浏览器状态：未启动、待登录、可用、执行中、需要用户处理。
- 岗位列表：网页链接、岗位名称、公司、JD 摘要、ATS、最近状态。
- 每个岗位的“自动填写”按钮。
- 多选后的“开始本批次”按钮。
- 最近一次字段审核报告。

### 6.2 执行页

- 当前岗位、URL（移除查询参数）、页面步骤和已用时。
- `盘点 → 匹配 → 填写 → 回读 → 审核` 状态流。
- 已完成、待人工、失败和安全阻断数量。
- “暂停”始终可用；“最终提交”永不出现。
- 当用户需要操作时，给出一个明确原因和返回条件，不展示技术堆栈。

### 6.3 审核页

每个字段显示：

| 招聘网页字段 | 网页状态 | 个人档案来源 | Agent 动作 | 审核结论 |
| --- | --- | --- | --- | --- |
| 姓名 | 已填写 | `basic.fullName` | 回读一致 | 内容一致 |
| 实习公司 | 空白 | `workExperiences.0.company` | 创建记录后写入失败 | 有信息，但程序未成功填写 |
| 紧急联系人 | 空白 | 无对应资料 | 未写入 | 个人信息缺失 |
| 期望城市 | 已填写 | `jobPreference.preferredCities` | 精确选项回读 | 格式及选项正确 |
| 自我评价 | 已填写 | `answers.selfEvaluation` | 语义匹配 | 部分相关，建议审核 |
| 验证码 | 空白 | 不适用 | 安全阻断 | 必须本人处理 |

报告支持按“只看需要我处理”“只看程序失败”“查看全部”筛选。

## 7. 端到端用户流程及验证方案

| 步骤 | 用户行为 | 系统行为 | 完成标准 | 可验证方案 |
| --- | --- | --- | --- | --- |
| U01 安装 | 运行桌面安装包 | 安装本机应用，不安装扩展 | Chrome/Edge 扩展列表无本产品；主程序可启动 | 在干净 Windows 用户上录制安装；检查 `chrome://extensions`、进程和安装清单；产物保存版本、哈希、签名状态 |
| U02 首次启动 | 阅读边界并确认创建求职浏览器 | 创建独立用户目录，启动可见 Chrome/Edge 和本地受限控制通道 | 默认浏览器资料未被使用；重启后专用会话可恢复 | 检查启动参数和目录；默认 profile 文件哈希/修改时间不变；端口只监听 loopback；关闭应用后无遗留监听 |
| U03 登录 | 在专用浏览器中自行登录招聘网站 | 仅观察页面可用状态，不读取或保存凭证 | 再次启动后网站会话由浏览器 profile 自行保持 | 人工登录并重启；静态与运行日志扫描不得出现密码、Cookie、Authorization 或 token |
| U04 准备档案 | 导入简历并补充档案 | 本地解析、结构化并显示缺失项 | 用户可编辑所有来源数据；不上传简历文本到外部服务 | 断网完成导入；进程网络审计为零；本地数据库重启后一致；原始简历正文不进入日志 |
| U05 添加岗位 | 粘贴真实岗位 URL | 打开真实公开页面，提取岗位名称、公司和 JD，并形成岗位卡 | 卡片展示链接、岗位名称、JD 和按钮；失败时说明原因 | 对保留的真实 URL 逐个核对页面标题/JD；记录 E2 时间和无查询路径；不使用复制页面 |
| U06 授权 | 点击单岗位“自动填写”或一次“开始本批次” | 生成绑定岗位集合、允许 origin、时限和动作范围的批次授权 | 授权外页面、过期请求和重放请求被拒绝 | 协议测试覆盖错 URL、换 origin、过期、重放；真实页验证 Agent 不读取未列入批次的标签页 |
| U07 盘点字段 | 无额外操作 | 在真实页识别当前步骤、分区、可见字段、动态条件和安全控件 | 每个可达逻辑字段获得稳定匿名引用；不读取密码/Cookie | 与独立人工标注逐字段比对；字段盘点率 100%；扫描前后页面值和记录数不变 |
| U08 制定填写计划 | 无额外操作 | 以档案路径、ATS 规则和页面语义生成计划；不确定项保持人工 | 每个字段恰有一个计划结论，且不会凭空生成档案值 | 用真实页标注计算映射正确率；故意缺失档案字段必须落入 `profile_missing`；模型输出不能绕过策略 |
| U09 创建重复记录 | 无额外操作 | 按档案记录数有界创建教育、实习、项目等条目 | 不漏创建、不重复创建、不删除用户已有记录 | 真实页记录写前/写后计数；同一批次重跑后记录数不增加；跨崩溃恢复仍幂等 |
| U10 填写并回读 | 无额外操作 | 通过类型化动作填写文本、选项、日期和富文本；每次写入后回读 | 仅允许字段发生变化；没有回读结果不得标记成功 | 真实 E4 逐字段 expected/actual 布尔比对；记录主策略与最多一次降级；错误控件写入为零 |
| U11 安全暂停 | 处理验证码、身份项、上传确认或登录失效 | Agent 停止对应动作，保持检查点并解释下一步 | 用户处理后可继续；暂停期间无后台点击 | 在真实页或浏览器安全测试中触发阻断；动作日志证明暂停后零写入；恢复前重新确认页面状态 |
| U12 生成审核 | 查看报告 | 合并字段盘点、档案来源、动作和回读结果 | 全部字段都有唯一结论；空白原因明确 | 审核行数等于人工字段分母；JSON schema 校验；结论互斥性测试；随机抽查与页面一致 |
| U13 批次继续 | 无额外操作或处理阻断后点击继续 | 保存检查点，转到下一岗位；崩溃后从最后已验证动作恢复 | 不重复填写已完成岗位，不跨岗复用过期字段引用 | 强制结束进程并重启；核对岗位/步骤/动作账本；重跑后零重复记录、零越界页面 |
| U14 用户提交 | 审核后自行在网页提交 | Agent 结束控制并只显示“等待用户提交” | 最终提交完全由用户完成 | 所有协议、UI 和运行日志中不存在 submit 能力；真实验收监听页面提交控件点击和投递请求均为零 |
| U15 BOSS 批次沟通 | 选择岗位范围、消息规则和每日上限后授权一次 | Agent 可在授权范围内浏览并发送允许类别消息，异常问题暂停 | 每条外发消息可追踪、无重复、无越界承诺 | 先 E3 只读，再用一个用户指定真实会话做单条 E4；核对发送文本、目标、时间和幂等键；超限/敏感问题必须阻断 |

## 8. 字段盘点、映射与审核规范

### 8.1 字段分母

“全部字段”指在用户档案和当前页面条件下，通过允许的展开、切换步骤和有界创建记录操作可到达的逻辑输入项。密码、验证码、文件、身份证、同意项和最终动作同样进入盘点报告，但不进入普通自动填写成功率分母。

以下内容不算字段：纯展示文本、布局容器、装饰图标和重复渲染但指向同一逻辑值的隐藏镜像控件。

条件字段的处理：

- 条件与用户档案不相符：`conditional_not_applicable`。
- 条件相符但字段尚未展开：Agent 可执行已审核的可逆展开动作，再纳入分母。
- 需要先修改服务器草稿才能显现：授权前告知；不能安全探索时标记 `unreachable_requires_user`。

### 8.2 唯一审核结论

每个字段必须且只能得到以下一个终态：

| 代码 | 用户结论 | 触发条件 |
| --- | --- | --- |
| `filled_match` | 已成功填写，内容一致 | 本批次写入并回读等价 |
| `already_match` | 页面原有内容与档案一致 | 未写入，规范化比较一致 |
| `profile_missing` | 个人信息缺失 | 页面有字段，档案无证据值 |
| `write_failed` | 有信息，但程序未成功填写 | 有档案值且允许写入，但回读失败 |
| `unsupported_control` | 当前控件暂不支持 | 控件能力不在内核范围 |
| `ambiguous_review` | 内容可能相关，建议审核 | 多个档案来源或语义无法唯一确定 |
| `sensitive_confirmation` | 需要本人确认后填写 | 身份、政治面貌等敏感字段 |
| `manual_verification` | 必须本人处理 | CAPTCHA、短信、人脸、扫码或登录 |
| `file_confirmation` | 等待确认文件 | 需要用户确认具体附件和目标字段 |
| `conditional_not_applicable` | 当前条件下不适用 | 业务条件明确不成立 |
| `site_policy_blocked` | 因网站规则停止自动化 | 站点条款或风控不允许继续 |
| `unreachable_requires_user` | 页面步骤需要本人操作 | 无法安全展开或导航 |

最终提交控件作为 `blocked_action` 单独进入动作审计，不属于档案字段。

### 8.3 来源与相关性

- 档案来源必须是稳定路径，例如 `workExperiences.0.company`，不能只写“来自简历”。
- 确定性别名、ATS 字段契约和用户纠正记忆优先；AI 只能提出候选映射。
- 开放题必须记录所使用素材、题目要求覆盖度和长度约束。仅关键词相近但未回答题目时标记 `ambiguous_review`。
- 不允许用职位 JD 推断用户没有提供的学校、成绩、经历、技能年限或身份信息。

## 9. 功能需求

### FR-01 零扩展桌面运行时

桌面应用负责启动、发现、连接和关闭求职专用浏览器。生产环境优先使用系统已安装 Chrome/Edge 的独立 profile；测试环境可使用固定版本 Chrome for Testing。浏览器必须为 headed 模式。

验收：

- 安装包不包含扩展 manifest，也不提示加载扩展。
- 主流程不调用 `chrome.runtime`、`chrome.tabs`、`chrome.debugger` 等扩展 API。
- 浏览器使用非默认 `user-data-dir`，调试端口动态生成且只监听 `127.0.0.1`。
- 控制通道需要每次启动随机能力令牌；另一个本机进程无法无令牌调用。
- 应用退出时正常关闭或明确交还专用浏览器，不影响用户日常 Chrome。

验证：Windows 干净用户安装测试、端口审计、进程参数审计、默认 profile 不变证明、无扩展证明、异常退出重启测试。

### FR-02 类型化浏览器内核

Agent 只能调用以下意图级能力：`listJobs`、`openJob`、`getPageState`、`findFields`、`expandSafeSection`、`createRepeatableRecord`、`fillText`、`chooseExactOption`、`setDateRange`、`confirmFile`、`waitForState`、`auditFields`、`pause`。内核可以在内部使用 CDP，但不得向模型、CLI 或插件暴露任意 JavaScript、任意 CSS/XPath、任意坐标点击、原始 CDP 或 Cookie 接口。

验收：协议 schema 拒绝未知动作、任意脚本、任意 selector、submit、delete、cookie 和 credential 操作；页面引用在导航或 DOM 变化后过期；所有写入都有动作前检查和动作后回读。

验证：协议负例、恶意模型输出、过期引用、导航竞争、错误 origin、重复 requestId 和进程重启测试；代码静态扫描无公共 `/eval`。

### FR-03 本地档案与岗位中心

复用现有档案 schema、简历解析和补充字段。岗位卡展示链接、岗位名称、公司、JD、ATS、状态和自动填写按钮。个人值本地加密存储；默认不发送到云端。

验收：断网可编辑档案和运行确定性匹配；岗位 URL 去除 query/fragment 后入日志；删除数据后本地不可恢复；没有内置用户档案。

验证：断网测试、数据库迁移测试、导入/导出/删除测试、日志隐私扫描、岗位元数据与真实页面人工核对。

### FR-04 一次批次授权

授权对象包含岗位 URL 列表、允许 origin、过期时间、普通填写动作和选定档案版本。默认 30 分钟，最长 2 小时。新增岗位、跨 origin、敏感字段、附件和 BOSS 外发消息不继承普通填写授权。

验收：批次内不要求逐字段点击；批次外零读取零写入；暂停/撤销立即生效；刷新后必须重新确认页面身份但无需重复授权未过期批次。

验证：状态机和能力令牌测试；真实批次含至少三个岗位；插入未授权标签页证明不可访问；撤销后动作计数为零。

### FR-05 全字段盘点与动态页面探索

扫描主文档、同源 iframe、开放 Shadow DOM、折叠区、分页/步骤和与当前档案相关的条件字段。跨源 iframe、关闭 Shadow DOM 和 Canvas 表单必须明确报告不可达。

验收：真实页面人工标注分母与 Agent 审核行数一致；重复控件合并为逻辑字段；动态记录创建后重新盘点；不得为探测而删除或清空用户草稿。

验证：每个真实验收页面都有独立标注者的字段清单；E3 比对达到 100%；页面扫描前后记录数和值不变。

### FR-06 确定性优先的 ATS 适配

优先级固定为：用户纠正记忆 > 公司级数据覆盖 > ATS 家族规则 > 通用语义匹配 > 用户明确开启的 AI 候选。适配声明只表达字段语义、控件能力、步骤和验证规则，不携带可执行脚本。

验收：修复安克公司级叫法不会改变小米公共规则；同一飞书家族至少三个公司 E4 后才晋升公共规则；未知题目默认人工审核。

验证：跨公司差异矩阵、规则优先级单元测试、真实多租户回归、变更影响报告和错误映射为零。

### FR-07 验证写入与幂等恢复

每个动作执行 `重新定位 → 安全检查 → 写入 → 等待稳定 → 规范化回读 → 记录结论`。主策略失败最多允许一次已注册降级策略。不得把事件已发送、元素值暂时变化或隐藏 input 变化视为成功。

验收：写入后浏览器可见值或组件已选状态与档案等价；动作账本使用幂等键；重跑不会重复创建记录或重复发送消息。

验证：真实页面逐字段布尔回读、强制刷新/SPA 导航/进程终止恢复、重复执行同一批次、主策略和降级策略计数。

### FR-08 字段级审核报告

报告同时面向用户和评测系统。用户看到自然语言结论；机器记录字段匿名引用、步骤、标签、控件类型、required、档案路径、策略、尝试次数、终态和失败类别。仓库证据不含页面值或档案值。

验收：每个字段唯一终态；报告分母与独立标注一致；任何空白行都有原因；报告能定位“资料缺失”与“程序失败”的不同修复责任。

验证：JSON schema、互斥/完备属性测试、真实页人工抽查、敏感值扫描、指标从报告自动计算且可复算。

### FR-09 人工接管与安全边界

遇到登录、CAPTCHA、短信、人脸、扫码、身份、敏感字段、文件确认、站点规则阻断或最终提交时暂停。文件上传只能由用户确认本地文件和目标字段后执行；Agent 不获得任意文件路径能力。

验收：暂停原因明确；用户处理后重新盘点再继续；所有最终提交入口在协议层不可表示；网站可能自动保存时授权前提示。

验证：安全负例矩阵 100% 阻断；监听提交按钮和投递网络动作均为零；附件令牌单次、限时、限 PDF、绑定目标字段。

### FR-10 BOSS 有界自动沟通

BOSS 能力晚于表单 MVP。用户为一批岗位配置公司/岗位范围、消息模板、事实来源、每日上限、有效时间和允许消息类别。Agent 可发送初次问候、简历事实回答和约面时间候选；薪资承诺、接受 offer、提供身份证明、转账、外链登录、附件发送及未知敏感问题必须暂停。

验收：每条外发消息在发送前通过事实和范围策略；同一岗位不重复发送；目标联系人、岗位和消息均可追溯；用户可立即撤销批次。

验证：先在真实 BOSS 登录页完成 E3 只读标注；再由用户指定一个真实会话完成单条 E4；核对发送目标与文本；重复、超限、事实外问题和撤销后发送全部为零。若平台条款或风控不允许，标记 `site_policy_blocked`，不尝试规避。

## 10. 技术架构

```text
桌面 React UI
  ├─ 本地档案与岗位库
  ├─ 批次授权与审核报告
  └─ Agent Orchestrator
        ↓ 仅类型化意图
安全浏览器内核（Electron main / Node）
  ├─ 会话、origin、时限与幂等策略
  ├─ ATS 家族适配器与公司覆盖
  ├─ 页面状态、动作、回读与日志
  └─ CDP transport
        ↓ loopback + 独立 user-data-dir
求职专用 Chrome/Edge（可见）
        ↓
真实招聘网站
```

### 10.1 MVP 技术选择

- 桌面壳：Electron。原因是最大化复用现有 React/TypeScript、Node 脚本和领域模块。
- 浏览器连接：Chrome DevTools Protocol；生产连接系统 Chrome/Edge 的独立求职 profile。
- QA 浏览器：固定版本 Chrome for Testing，仅用于浏览器内核重现和发布测试，不代替真实招聘页验收。
- 本地存储：SQLite 或等价嵌入式数据库；敏感列使用操作系统凭据保护能力加密。
- Agent：确定性工作流为主，模型只做受限规划/语义候选；浏览器动作始终经过内核策略编译。
- 进程通信：优先 Electron IPC；若拆为守护进程，使用 loopback/命名管道、随机令牌和每次启动轮换。

### 10.2 对 BossHunter 的借鉴边界

可借鉴：可见浏览器、CDP 会话连接、页面内组件交互、写后验证和长任务轮询。

不可照搬：对 Agent 暴露任意 `/eval`、任意 selector、任意坐标、任意文件路径或原始 CDP。产品接口只接受经过 schema 校验和安全策略约束的业务意图。

## 15. 发布、回滚与风险

### 15.1 发布策略

- Alpha：仅小米 E4，供当前用户使用。
- Private Beta：至少三个 Feishu 公司 E4 + 一个非 Feishu E4。
- MVP：M5-M8 完成，扩展不再是产品依赖。
- BOSS 能力作为独立开关，不阻塞表单 MVP，也不随表单授权自动启用。

### 15.2 回滚

- ATS 规则、桌面应用和浏览器内核分别版本化。
- 新规则使任一真实回归出现错误写入时，自动降级到上一已验证规则或人工模式。
- 数据迁移必须可回滚；不得自动删除旧扩展档案，用户确认迁移成功后才能清理。
- 浏览器连接失败时保留岗位和执行账本，不尝试切换到默认 Chrome profile。

### 15.3 主要风险及验证

| 风险 | 控制 | 早期验证 |
| --- | --- | --- |
| Chrome 调试政策变化 | 独立 profile、版本检测、Edge/Chromium 兼容层 | 每次发布运行浏览器启动矩阵 |
| 招聘站组件漂移 | ATS 家族能力 + 公司覆盖 + E3 漂移检测 | 真实页定期只读盘点，分母变化即降级 |
| 自动保存污染草稿 | 授权前提示，只用真实档案，禁止虚假测试 | E4 前人工确认站点保存行为 |
| 模型误判 | 确定性优先、模型仅提议、策略编译和回读 | 恶意/错误模型输出测试 |
| 本机接口被滥用 | loopback、随机令牌、最小 API、无任意 eval | 无令牌/重放/跨进程调用负例 |
| BOSS 账号风控或条款风险 | 站点政策门、限速、只读优先、禁止规避 | E3 前完成政策检查，失败即阻断 |
| 个人信息泄露 | 默认本地、日志无值、私有证据不入库 | 网络审计、secret/PII 扫描、删除测试 |

## 16. 未决产品决策

以下问题不阻塞 M1-M5，但必须在对应里程碑前由用户决定：

1. 桌面安装包是否需要公开发布，还是先只供个人使用。
2. AI 候选和 BOSS 消息使用本地模型、用户自备 API，还是完全不启用模型。
3. BOSS 自动沟通允许的消息类别、每日上限和工作时段。
4. 身份字段采取“永远手填”还是“本地保存、每次确认后填写”。
5. 真实页私有截图和运行日志的本地保留期限。

在这些决定前，默认值均取最小权限：个人使用、确定性填写、BOSS 关闭、身份手填、私有证据手动清理。
